# Connect support entry

Both browser-to-MusicScale and MusicScale-to-Connect preserve the same transient user bearer in Authorization and X-Connect-User-Authorization, matching the established Cloud Run transport. Connect still verifies the selected token through the canonical Hub; the extra header is never authority. No credential enters a draft URL, logs or persistent storage.

The existing SupportModal keeps email support and adds a PT/EN/ES manual WhatsApp button only when VITE_CONNECT_SUPPORT_ENABLED=true. It uses current AuthContext identity/organization, obtains a transient Firebase token on explicit click and calls POST /api/v1/connect/support-draft with locale only. Account/organization changes and unmount invalidate pending results; failures close the blank popup and preserve email support. No automatic message or token persistence.

The server route sits after the existing Hub trial gate and calls only the fixed official Connect support-draft endpoint. Product is server-fixed musicscale; requested organization comes from the existing scope header and remains untrusted until Connect revalidates Hub authorization. No role/UID/product/phone/body scope override. Validates the returned manual HTTPS wa.me URL, expiry and product, strips unrelated/private fields and refuses redirects. No business rule is duplicated.

The authenticated Core draft boundary is published. Official MusicScale builds opt into the explicit manual support entry after the canonical 401 gate; ordinary builds remain opt-in. Local 21/21 UI/relay simulations, TypeScript and equivalent frontend/server builds passed. These are synthetic contract and browser-behavior tests, not a claim of real-account Meta metadata QA or physical push delivery. Promote only the reviewed scoped slice with normal release/version gates, preserving other main features and customer data.

Official Firebase releases now set VITE_CONNECT_SUPPORT_ENABLED=true and require a live canonical Core 401 before publishing. Ordinary local/test builds remain opt-in. This exposes only the explicit manual draft action; Core/Hub freshly authorize each real caller and Meta metadata failures preserve existing email support. No automatic message or product-routing activation occurs. Automated UI/relay/Core contract tests use synthetic identities and destinations; they do not certify a real user session or physical device.

## Public support entry — 2026-10-23

The support modal now always offers a localized subject selector and public Connect contact link. It no longer requires successful app authentication, an organization, a plan or the VITE_CONNECT_SUPPORT_ENABLED build flag to contact the official support channel. The existing authenticated signed-draft endpoint/proxy remains available unchanged to existing consumers. Public intake metadata is explicitly self-reported; it never authenticates users or grants app data access. Email remains available.
